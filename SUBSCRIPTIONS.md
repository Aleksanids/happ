# Стриж — подписки для Happ

**⚠ ТОРРЕНТЫ ЗАПРЕЩЕНЫ.** В обеих подборках Xray блокирует распознаваемый BitTorrent: обычный TCP BitTorrent и UDP uTP. Правило действует в ручных локациях и «⚡ Авто» до прямого российского маршрута и выбора VPN; штатная обработка DNS сохранена перед ним, чтобы uTP-эвристика не блокировала корректные короткие DNS-запросы. Это клиентское ограничение: зашифрованный, замаскированный и нераспознанный P2P, включая нераспознанный DHT, полностью им не контролируется. Блокировки аккаунтов или санкций провайдера эта система не реализует.

В текущем формате полного JSON на raw.githubusercontent.com предупреждение опубликовано здесь. Баннер `announce` Happ документирует через HTTP-заголовок или префикс URI-списка; совместимость такого префикса с нашим JSON не подтверждена. Подписки сохраняют рабочий JSON без неподдерживаемых заголовков, metadata и фиктивной серверной строки.

Две подписки на прежних постоянных HTTPS-ссылках GitHub, без собственного домена:

- [Стриж — открыть в Happ](https://aleksanids.github.io/happ/#speed) — быстрые проверенные выходы из зарубежных стран; российские выходы исключены.
- [Стриж · Dots — открыть в Happ](https://aleksanids.github.io/happ/#dots) — быстрые проверенные выходы из разрешённого для этого профиля набора стран; США имеют приоритет, когда проходят проверку.

Для открытия подписок в Happ из браузера используйте:

- [Открыть «Стриж» в Happ](https://aleksanids.github.io/happ/#speed)
- [Открыть «Стриж · Dots» в Happ](https://aleksanids.github.io/happ/#dots)

Эти HTTPS-ссылки открывают небольшую страницу GitHub Pages, которая пытается передать фиксированную ссылку импорта обработчику Happ. Если браузер запросит разрешение открыть приложение, подтвердите его. Если автоматический переход заблокирован, на странице остаётся кнопка «Открыть в Happ». Happ должен быть установлен. Адреса обновления в приложении остаются прежними: `https://raw.githubusercontent.com/Aleksanids/happ/main/speed.txt` и `https://raw.githubusercontent.com/Aleksanids/happ/main/dots.txt`. Это служебные источники данных; при обычном открытии в браузере они показывают JSON.

Обе подборки остаются разными, но у каждой один постоянный источник для Windows и Android. После обновления устройства получают опубликованные списки и правила; личные замеры ping и текущий выбор Auto выполняются отдельно в сети каждого устройства. Если карточка уже добавлена, обновляйте её; повторный импорт может создать ещё одну карточку. Схема импорта используется в [исходной конфигурации Remnawave Subscription Page для Happ](https://github.com/remnawave/subscription-page/blob/main/frontend/public/assets/app-config.json). Открытие custom scheme зависит от браузера/клиента и наличия установленного Happ; обычные HTTPS-ссылки выше доступны для импорта через буфер.

Каждая содержит отдельную первую строку **⚡ Авто** и до **10** ручных серверов с флагами и русскими названиями стран. При нескольких серверах одной страны добавляется номер. Страна определяется по фактическому выходу прокси; подписи из исходных списков не считаются доказательством. Состав серверов и стран может меняться при новых проверках. Название уже добавленной карточки Happ меняется один раз в меню этой карточки: «Авто — Скорость» → «Стриж», «Авто — Dots» → «Стриж · Dots». Ссылки менять и добавлять повторные подписки не требуется.

Отдельный [reserve.json](https://raw.githubusercontent.com/Aleksanids/happ/main/reserve.json) хранит большой резерв общедоступных кандидатов и историю проверок. Его тип `UNVERIFIED_CANDIDATES`: наличие записи не означает, что сервер работает сейчас. В нём есть число попыток, последний результат, время последней успешной проверки и её исторические показатели. Непроверенные или ранее успешные записи не подставляются в новую подписку без успешной проверки в текущей сборке. Резерв не является третьей подпиской для импорта в Happ.

Резерв ограничен 5000 записями и 4 МБ; фактический размер может быть меньше из-за доступности источников и длины конфигураций. Он пополняется из девяти фиксированных публичных списков. Новые кандидаты продолжают поступать и при заполненном резерве: сохраняются сильные прежние варианты, часть устаревших или неудачных записей постепенно вытесняется. История остальных сохраняется между запусками. Повреждение состояния не вызывает скрытого сброса истории.

За один запуск проверяется до 160 кандидатов, не более четырёх одновременно, с ограничением времени. Отбор чередует повторные проверки прежних быстрых серверов, новые и давно не проверявшиеся варианты и повторные попытки после ошибок. Вся многотысячная база не проверяется одновременно. Короткий список строится только из успешных результатов этого запуска; сортировка учитывает задержку и разброс трёх измерений. Это проверка задержки и HTTPS-соединения, а не измерение скорости скачивания. В Dots сначала выбираются наиболее быстрые допустимые результаты; если проверенные США есть, но не попали в десятку, самый медленный заменяется самым быстрым проверенным США. Если США сейчас не проходят проверку, используются рабочие Канада, Япония, Сингапур, Австралия или Южная Корея; неработающий США не добавляется ради сохранения страны. Затем США показываются первыми среди ручных серверов.

Каждый включённый сервер проходит два настоящих HTTPS-запроса через изолированный прокси для проверки страны выхода и третий запрос к https://www.gstatic.com/generate_204, который используют «Авто» и наблюдаемая проверка строк Happ. Дополнительно обязательно проверяется DNS-over-HTTPS через этот же прокси: запрос example.com к одному из двух закреплённых DNS-адресов должен вернуть корректный публичный IP. Если HTTPS работает, а DNS не проходит, такой сервер в новую подборку не включается. Третий запрос обязан завершиться HTTP 204 с корректным отсутствием тела. Его лимит — 5 секунд, в соответствии с тайм-аутом штатного observatory установленного Xray; успешный ответ за 5–8 секунд больше не допускается как пригодный для Auto. Все три HTTPS-проверки и дополнительная DNS-проверка выполняются в общем ограничении времени. Российские выходы отклоняются до включения в список. Перед публикацией каждый выбранный узел дополнительно запускается как полный клиентский JSON в установленном Xray: через его встроенный DNS проверяются example.com и целевой www.gstatic.com, затем выполняется HTTPS-запрос к Gstatic со строгой проверкой TLS и HTTP 204. Системный DNS сборщика для этого целевого запроса не используется. Отказавший узел исключается из обеих подборок; замена берётся только из успешных результатов этого же запуска и проходит такую же полную проверку. Результат привязан к точной конфигурации, закреплённому адресу сервера и текущим правилам; к моменту сохранения новой сборки он не старше 120 секунд. Отправку этой сборки в GitHub выполняет отдельная задача; серверные замеры относятся ко времени сборки. Проверки используют до четырёх параллельных работников и общий лимит сборки 900 секунд. Если времени или пригодных узлов для одной из подборок не хватает, новая пара файлов не публикуется, сохраняется прежняя с её исходным возрастом. Полные конфигурации также проверяются парсером установленного Xray. Ошибка или тайм-аут не выдаются за доказанную блокировку РКН. Проверка отражает сеть сборщика; доступность на другом устройстве и у другого провайдера может отличаться. `n/a` в Happ означает отсутствие результата клиентского замера; если через выбранную строку работает интернет, это само по себе не признак неработающего сервера. Способ проверки, тестовый адрес и ограничения времени клиента могут отличаться от серверной проверки. Непроверенные узлы и ошибки измерений не маскируются выдуманным пингом.

**⚡ Авто** использует штатные Xray leastPing/observatory и выбирает наблюдаемый минимум задержки среди членов своей подписки для новых VPN-соединений. Интервал между раундами — 5 секунд; само время проверки тоже влияет на переключение. Уже открытые соединения между серверами не переносятся. Более частые проверки расходуют дополнительный трафик и заряд; полное время обнаружения отказа включает длительность раунда и ожидание, поэтому мгновенное переключение не обещается. Это переключение внутри активного Auto; локальное «н/д» в ручной карточке не удаляет её из статической подписки. В текущем полном JSON подробность локального журнала снижена до warning, access-log отключён; dnsLog и автоматическая отправка журналов не включены. Сообщения об ошибках могут содержать адреса и остаются на устройстве. Это отдельный процесс от обновления подписки на GitHub.

В обоих профилях сохранён выбранный владельцем режим: **российские сайты напрямую, остальные через VPN**. Сначала проверяются российские домены (.ru, .su, .рф и встроенная категория российских сервисов), затем российские IP-диапазоны. Например, ЕИС, Яндекс и VK могут идти напрямую, включая известные российские сервисы в .com. Неизвестное направление остаётся на VPN. Используются штатные geoip/geosite установленного Happ/Xray, распознавание HTTP/TLS-домена и IPOnDemand. Это классификация по базам доменов и адресов, поэтому неполные списки и зарубежные CDN могут потребовать уточнения.

Обе ссылки отдают одинаковые полные JSON-профили для Windows и Android; отдельной мобильной подписки нет. В каждой ручной локации и Auto задан DNS-over-HTTPS с двумя IP-адресами: 1.1.1.1 и 8.8.8.8. Обычные DNS-запросы на порт 53 обрабатывает встроенный DNS. Российские домены разрешаются через прямой маршрут, остальные — через выбранный VPN-сервер или Auto. Проверка TLS включена. При ошибке встроенного DNS прямой маршрут не переключается скрыто на системный DNS. Полные конфигурации проверяются установленным Xray и реальным прокси на сети сборщика. Это не является наблюдением сети физического Android-устройства; доступность у разных провайдеров может различаться.

Правила встроены в каждую полную JSON-конфигурацию и действуют для ручных локаций и Auto. Прямой российский маршрут не участвует в балансе Auto и не служит запасным выходом для зарубежного трафика: если все VPN-узлы недоступны, зарубежный трафик блокируется.

Обе существующие задачи Windows переведены на **30 минут**. Независимое чтение подтвердило сохранение остальных настроек запуска и прав доступа. Первая сборка обновлённой схемы действительно завершилась от LOCAL SERVICE с кодом 0; отдельная задача пользователя по расписанию действительно опубликовала новое поколение с кодом 0. В первом успешном запуске 23.10.2026 резерв содержал 3658 кандидатов: проверено 160, успешно подключились 31; в каждой подписке опубликованы 10 ручных серверов и Auto. Эти числа относятся к первому запуску; последующие подборки могут отличаться.

Документированный интервал автоматического обновления подписки в Happ задаётся целыми часами, минимум один час. Обновление файлов на сервере каждые 30 минут и автоматическое скачивание клиентом — разные настройки. Новую опубликованную версию можно получить сразу кнопкой обновления у каждой подписки; затем переподключить выбранную локацию или Auto.

`manifest.json` содержит поколение, названия профилей, число ручных серверов, время проверки, срок свежести, контрольные суммы и сведения о резерве. Обе подписки, резерв и manifest публикуются одним GitHub-коммитом. Незавершённый, устаревший или несогласованный снимок не отправляется. Срок свежести — шесть часов. При ошибке сохраняется последняя опубликованная версия; это не продление её фактической свежести.

Публикация выполняется существующей задачей обычного пользователя Windows через защищённое системное хранилище авторизации GitHub. Она использует интерактивный сеанс владельца: отключение RDP не равно выходу из Windows, а публикация после полного выхода из учётной записи не гарантируется. Сборщик работает от LOCAL SERVICE. Новые службы и дополнительные планировщики не создавались.

Использованы только фиксированные файлы общедоступных кандидатов; Group2 с подписками сторонних сервисов исключена.

Платные подписки и личные ключи владельца не переносились. Сборочный сервер собирает и проверяет конфигурации; VPN-трафик пользовательского устройства идёт на выбранный выходной сервер. Dots задаёт сетевые выходы; права доступа аккаунта OpenAI остаются отдельным условием.
